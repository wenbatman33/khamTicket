# 寬宏售票填寫輔助（kham.com.tw）

一個**只做填寫的** Chrome 擴充功能。看到元素就幫你填、幫你點，其餘一概不碰。

## 它只做四件事

| 看到什麼 | 做什麼 |
|---|---|
| **訊息視窗**（實名制提醒之類） | 自動按「Ok」。**錯誤訊息、以及任何需要你決定的確認框（訂單／付款／有「取消」可選的）一律不代按** |
| **優先購序號欄位** | 自動填入設定的序號並按「送出」。照原樣填、**不裁切** |
| **張數欄位** | 自動填入張數、勾「接受不連位」 |
| **驗證碼** | **只放大圖片＋把游標放進去，其餘零接觸**：不監聽 input／keydown／組字、不改你打的字、不判斷打滿沒、不自動送出、不碰圖片 `src`。2026-09-18 使用者指示「一監聽都會有錯誤」 |

## 監票（勾選，持久）

擴充功能最上面的「**👁 監票**」勾選框（網頁面板標題列也有同一顆）。勾著的時候，只要在票區頁：

- 每秒按一次網站自己的「更新票數」（由網頁環境觸發它綁的 handler，面板會顯示「按到：…」）
- 網站一重畫票區表就立刻讀，**有票立刻進場**（優先挑空位 ≥ 你設的張數，沒有就挑最多的）：
  從座位圖的 `Send()` 或列的 `rel="a24"` 取出 GROUP_ID，自己組出
  `UTK0201_001.aspx?PERFORMANCE_ID=…&GROUP_ID=…&PERFORMANCE_PRICE_AREA_ID=…` 直接跳。
  **不靠網站的點擊 handler** —— 靠模擬點擊會賭它綁在 tr／td／jQuery 委派哪一層，賭錯就是看得到票卻一下都沒點到
- **一進到購票頁（張數／站席／選位）就自動取消勾選並停手**，不會在你打驗證碼時把你帶走
- 點進去後 2.5 秒還停在票區頁（撲空、被彈回）→ 不管網站說什麼，自動繼續監
- F5、從張數頁按上一頁回來、換到別的票價的票區頁 → 都自動接著監，直到你取消勾選
- 「該票區已售完！」這類原生 `alert()` 被接掉，不再跳出擋住整頁的框，改右下角 toast

進了張數頁之後還是照四件事走：填張數、放大驗證碼，**驗證碼你打、加入購物車你按**。

2026-09-18 實測：回流票從出現到消失不到兩秒，人手來不及，所以有票就直接點。

## 它不做什麼

- 不挑場次、不點「立即訂購」
- 不挑票區、不點票區列、不碰站席頁的票區下拉
- 不自動換頁、不輪詢庫存、不監控回流票
- 不寫任何紀錄或頁面快照

**場次與票區由你自己選。** 這是刻意的：工具分不清哪一區已完售，猜錯只會浪費你的時間。

## 兩個前提

1. **驗證碼要你自己打。** 本工具不辨識驗證碼、也不代填帳號密碼。
2. **先登入會員再開搶。**

## 安裝

1. `chrome://extensions` → 右上角開啟「開發人員模式」
2. 「載入未封裝項目」→ 選這個資料夾
3. 改完程式碼要回到這頁按「重新載入」，**再重整網頁**
   （面板左上角會顯示版本，對不上就是新版還沒載入）

## 設定

| 設定 | 說明 |
|---|---|
| **啟用** | 總開關。關掉之後**完全不動作**：不關訊息視窗、不填、不送出 |
| **優先購序號** | 認證燈箱（附近有「優先購／Presale／卡友／驗證」字樣）裡的文字欄位一律填這個值，不看標籤寫序號還是卡號。**中國信託卡友的「卡號前 6 碼」也填這一欄。** 欄位被清空又出現會再填，連續送出 3 次沒過就停手；**你一碰鍵盤它就放手** |
| **填好就自動按「送出」** | 只管序號這一件事 |
| **每次填幾張** | 張數欄位要填的數字。剩餘或限購較少時就填那個數字 |

工具**不會**按「加入購物車」，也**不會**幫你勾「接受不連位座位」（網站預設沒勾就維持沒勾）。

頁面上的浮動面板標題列也有同一顆「自動送出」開關，搶票當下可以就地切換。

## 站席頁（`UTK0202_`）

票區是用下拉選單 `#PRICE` 選的。**工具不會幫你選**，你選好之後它才幫你填張數。

## 行為測試

```bash
bash tests/run.sh
```

用 headless Chrome 載入**跟真實網站同構的 DOM**，再載入真正的 `content.js`，檢查它到底做了什麼。

| 測試 | 檢查什麼 |
|---|---|
| `notice_ok` | 訊息視窗自動按 Ok；**錯誤訊息不可以被關掉** |
| `presale_box` | 序號欄位出現 → 填入 → 按送出 |
| `presale_wrapper` | 送出鈕被空殼 `div` 包住時，要點到裡面真正可點的那一顆 |
| `presale_reopen` | 燈箱關掉再開（同一個 input 被清空）→ 要再填一次、再送出一次 |
| `presale_handsoff` | **你一碰鍵盤，工具就不再填、不再送那個欄位**。設定裡留著錯的值時，你清掉自己打，它不會再填回去 |
| `qty_fill` | 站席頁沒選票區前不填；你選好之後才填。主開關關著也要填，但不可送出 |
| `captcha_untouched` | 驗證碼：打全形、打滿、按 Enter 都不可以有任何反應；圖不換；只放大＋聚焦 |
| `cart_checkout` | 購物車自動按「結帳」；**付款與送出訂單絕不能碰** |
| `watch_buyurl` | 有票 → 直接組購票網址跳（GROUP_ID 與票區 ID 正確） |
| `watch_stops_on_buypage` | 進購票頁：本分頁停手，但**勾選要保留**（被彈回才會自動繼續） |
| `presale_card` | 中信卡友「卡號前 6 碼」要填；**結帳頁的信用卡號絕不能碰**（同頁三個卡號欄位，只填認證那個） |
| `master_off` | 總開關關掉：**完全不動作** |
| `watch_refresh` | 監票：每秒按「更新票數」；某區售完→有票就點那一區（第一次只點一下），卡住會重試 |
| `watch_persist` | 監票是勾選：設定裡勾著，F5 之後不按任何鈕也自動繼續 |
| `watch_retry` | 點進去後網站毫無回應：2.5 秒沒到張數頁就自動繼續監；handler 綁在 `td` 也點得到 |
| `alert_soldout` | 原生 `alert()` 接掉不擋頁；點進去撲空（已售完）自動繼續監 |
| `no_navigation` | 同一頁有訂購鈕與票區表時：**只填該填的，絕不點、絕不換頁** |

## 2026-09-17 的教訓

這個工具在 BIGBANG 優先購當天被砍掉八成功能，原因值得記住：

1. **依頁面流程判斷會靜悄悄地全盤失效。** 判斷寫死成「網址是場次頁 + `.popoutBG` + `#ID1`」，真實的優先購畫面三個條件一個都不符，於是什麼都沒做。現在改成**元素驅動**：畫面上有什麼就做什麼。
2. **`has()` 被誤刪，`sweep()` 每次都丟 ReferenceError**，整組規則引擎全滅；例外被包在 promise 裡，主控台一片安靜。靠肉眼 review 沒抓到，是 `tests/` 抓到的。
3. **票價的刪除線不是完售。** 開賣當下的真實 HTML 顯示 `<s>` 每一列都有，跟有沒有票無關；完售的訊號是按鈕變成 `class='gray'` 的「已售完」。
4. **猜測式的自動化只會礙事。** 自動挑票價、自動進場、自動探路、跨票價監控、直達跳頁——全部移除。

真實 DOM 素材與當天還原出的場次對照表留在 `tests/fixtures/`。

## 使用範圍與限制

- 所有請求都由網站原有程式碼發出，本工具只填欄位與點按鈕
- 不辨識驗證碼、不代填帳號密碼
- 與寬宏售票無隸屬關係
