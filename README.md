# 寬宏售票表單填寫輔助（Chrome 擴充功能）

個人自用的表單填寫輔助工具，適用於寬宏售票 `kham.com.tw`，**以「電腦配位」為主**。
把原本要手動點的購票、場次、票區、張數改成依預先設定一次填妥，並把庫存與流程狀態顯示在畫面上。

本專案與寬宏藝術／寬宏售票無任何隸屬或合作關係。

## 兩個前提（很重要）

1. **驗證碼要自己打** — 工具不辨識、不繞過驗證碼。它做的是把驗證碼圖放大 1.6 倍、自動把游標移進輸入框，你打完 4 碼就自動送出；打錯時自動換一張新圖並清空重來。
2. **不代填帳號密碼** — 請**先登入會員**再開搶。工具偵測到未登入會顯示警告並拒絕送出。

## 網站的實際流程（實地追出來的）

| 頁面 | 網址 | 工具在這裡做什麼 |
|---|---|---|
| 節目頁 | `UTK0201_.aspx?PRODUCT_ID=…` | 開賣前守在這裡。到開賣時間就反覆按官方的「立即購票」，直到伺服器不再回「節目尚未啟售！」 |
| 場次頁 | `UTK0201_00.aspx?PRODUCT_ID=…` | 依「場次關鍵字」挑一場，按「立即訂購」 |
| 票區頁 **A 型** | `UTK0201_000.aspx?PERFORMANCE_ID=…` | 有「自行選位／電腦配位」兩顆按鈕。查庫存 → 命中就走**電腦配位** |
| 票區頁 **B 型** | `UTK0204_.aspx?PERFORMANCE_ID=…` | 同樣列票區，但**這條流程沒有電腦配位**。查庫存 → 命中就進選位頁，座位要自己勾 |
| 張數頁 | `UTK0201_001.aspx?…` | 電腦配位才會走到。填張數、勾「接受不連位」、放大驗證碼並聚焦 |
| 選位頁 | `UTK0205_.aspx?…` | B 型流程的終點。座位表是自訂繪製，**工具不代選座位** |
| 購物車 | `UTK0206_.aspx` | 通知加入成功；可選自動按結帳 |

一個容易誤會的地方：A 型票區頁的 `buyC` 初值實測是 `1`，且「自行選位」按鈕帶著 `red` 高亮 —— 也就是**該頁的預設是自行選位**，要電腦配位得自己按那顆按鈕。本工具不依賴這個預設值，它是直接組 `UTK0201_001` 的網址走電腦配位。

兩件實測出來的硬限制：

- **開賣前拿不到 `PERFORMANCE_ID`**，票區頁也進不去，所以開賣前只能守在節目頁。
- **這些頁面綁 session 的流程狀態**，直接用網址跳進去會被導回首頁；從 B 型（`UTK0204_`）的 session 硬跳電腦配位頁也一樣會被踢掉。工具偵測到被導回首頁會停手並要你重新從節目頁走一次。

## 安裝

1. Chrome 網址列輸入 `chrome://extensions`
2. 右上角開啟「開發人員模式」
3. 點「載入未封裝項目」，選擇這個資料夾（`/Users/batman_work/claude/kham_ticket`）
4. 工具列出現 🎫 圖示

## 使用流程

先登入寬宏會員 → **開賣前把分頁停在節目頁**（`UTK0201_.aspx?PRODUCT_ID=…`）→ 點工具列圖示設定 → 填開搶時間 → 開主開關。

| 設定 | 說明 |
|---|---|
| **自動搶票**（主開關） | 開＝自動按購票、選場次、查票、填表；關＝完全不動作，可按「立即執行」跑一次。**改動立即生效，不必按儲存** |
| **開搶時間** | `10:00` 或 `10:00:00`，留空＝進頁面就開始。時間到之前只顯示倒數 |
| **重試間隔** | 毫秒，預設 800。節目頁多久按一次「立即購票」、票區頁多久查一次庫存 |
| **場次關鍵字** | 多場次時用，例如 `2/27`。留空＝第一個可訂購的場次 |
| **票區優先順序** | 一行一個，由上往下試，搶到就停。比對忽略大小寫與空白，可只填一部分（填 `VIP` 會對到所有含 VIP 的票區） |
| **每次買幾張** | 上限自動夾在該場次的限購張數與剩餘數之內 |
| **剩餘不足時買剩下的** | 預設關：剩餘少於需求張數就換下一個票區 |
| **接受不連位座位** | 預設開，對應張數頁的同名勾選框 |
| **驗證碼輸滿自動送出** | 預設開，位數見進階設定（預設 4） |
| 進階：**票種優先順序** | 同一區有多種票價（全票／優待票…）時要哪個，逗號分隔。留空＝該區第一種 |
| **有分頁搶到後其他分頁停手** | 預設開。開兩個分頁搶不同場次時用，見下方說明 |
| 進階：**自動按結帳** | 預設關。加入購物車後自動按結帳；金額與場次請自行確認 |

搶票期間畫面左上角有常駐面板，顯示目前所在流程、嘗試次數、每個目標票區的餘位。抓住標題列可拖曳，位置記在 `localStorage`。

## 它實際在做什麼

### 節目頁：等開賣

開賣前按「立即購票」，伺服器只會回 `alert1('節目尚未啟售！')`。工具到了設定的開搶時間才開始，每隔一個重試間隔按一次官方按鈕，順手把跳出來的 jQuery UI 對話框關掉，直到回應變成導向指令（＝已啟售）就停手交還給網站。

### 票區頁：查庫存

- 這頁沒有任何自動更新，庫存要重新載入才會變。工具改用 `fetch` 只取這頁的 HTML 解析 `#salesTable`（實測約 85ms），**不整頁重載**。
- 解析每一列的票區名稱與空位數，依你的優先順序挑第一個買得到的。
- A 型（`UTK0201_000`）→ 直接前往電腦配位的張數頁
  `UTK0201_001.aspx?PERFORMANCE_ID=…&GROUP_ID=…&PERFORMANCE_PRICE_AREA_ID=…`
- B 型（`UTK0204_`）→ 點該票區走網站原生的 `Send()` 進 `UTK0205_` 選位頁，並提示座位要自己勾
- `GROUP_ID` 從票區列的 `rel` 屬性直接推出來：`rel="a18 a19 a20"` → `GROUP_ID=18`。這個屬性**原始 HTML 裡就有**，不必等座位圖。
  （座位圖 `<map area>` 的 `Send()` 呼叫裡也有同一個值，但那是頁面載入後才由網站 ajax 補上的，fetch 回來的 HTML 是 0 個 area。實測 FEniX 3 區、MUSIC EXPO 兩場共 16 區，`rel` 推算與座位圖的值完全一致。）
- 只有套票類活動（`SendA`，跳轉還要帶 `ACTIVITY_GROUP_ID`／`ACTIVITY_GROUP_ITEM_ID`）才會退回去等座位圖，最多等 4 秒。

### 張數頁：填表

- 讀 `input[KEY='TYPE_ID']` 取得該區所有票種，依票種優先順序挑一種，把張數寫進 `input[KEY='<票種ID>']`（網站是純 jQuery 讀值，寫入即生效），其餘票種歸零。
- 張數自動夾在 `QUANTITY_LIMIT`（限購）與 `LAST_AMOUNT`（餘位）之內。
- 勾選 `#ATYPE`「接受不連位座位」。
- 放大 `#chk_pic`、聚焦 `#CHK`，輸滿設定位數就呼叫網站原有的 `addShoppingCart()`。
- 送出結果由網站自己的回應判定：
  - 提示含「驗證碼」→ 自動換新圖、清空、重新聚焦，**不離開此頁**
  - 提示含「售完／不足／逾時」等 → 自動退回票區頁繼續搜尋，並把該票區冷卻 10 秒，換下一個目標
  - 提示含「帳號／密碼／登入」→ 停下來要你先登入
  - 回應帶導向指令 → 判定為加入購物車成功，發桌面通知並閃爍分頁標題

### 購物車頁

發通知提醒在保留時間內結帳；若開了「自動按結帳」會找結帳按鈕按下去。

> ⚠️ 購物車與結帳頁需登入才看得到，這兩頁的按鈕定位是以文字比對推測的，**尚未實地驗證**。第一次用建議關著「自動按結帳」，確認畫面後再決定要不要開。
> 實名制活動在結帳前要選入場人，這段流程工具完全沒有介入。

## 開兩個分頁搶不同場次

**可以，實測不會互相干擾。** 拿 MUSIC EXPO 10/24（`P1CXNJEX`）與 10/25（`P1CXXK2O`）兩場做過雙分頁測試：分頁 1 停在 10/24 的電腦配位張數頁，分頁 2 走完 10/25 的完整流程進到票區頁，回頭重新載入分頁 1，票區、餘位、驗證碼欄全都還在 —— 伺服器是按商品／場次分開記流程狀態的，不是只准同時進行一個。

工具本身也相容：座位圖快取、票區頁網址、票區冷卻都存在 `sessionStorage`（每個分頁各自獨立），兩邊不會混到。設定共用一份，但同一個活動不同天的票區名稱通常一樣，共用剛好省事。

真正的瓶頸是**驗證碼只有一雙手**。所以有一個選項「有分頁搶到後其他分頁停手」（預設開）：任一分頁加入購物車成功時會用 `chrome.storage.local` 廣播，其他分頁立刻暫停並在面板顯示，等你把搶到的那邊處理完。要讓其他分頁繼續搶，開擴充功能面板按「解除暫停」（該紀錄 10 分鐘後也會自動失效）。

> 順帶一提：兩場的票會進到**同一個購物車**，可以一起結帳，但保留時間各自倒數，先加入的先到期。

## 為了搶快做的事

| 做法 | 省下什麼 |
|---|---|
| `GROUP_ID` 從 `rel` 推算，不等座位圖 ajax | 最多 4 秒 |
| 票區頁第一輪直接讀當下 DOM 的庫存，不先發 fetch | 一次往返（實測約 85ms） |
| 查庫存用 `fetch` 解析 HTML，不整頁重載 | 每輪約 1 秒 |
| content script 用 `document_end` 注入，不等 `load` | kham 掛了 20+ 個廣告／追蹤腳本，省下的是它們的載入時間 |
| 開賣後前 3 秒把輪詢加密到最快 300ms | 第一波庫存釋出的命中率 |
| 倒數最後一段精準睡到開賣時刻 | 最多 50ms 的過衝 |
| 場次頁直接取 `onclick` 裡的網址導向 | 不繞事件處理 |

## 檔案結構

| 檔案 | 用途 |
|---|---|
| `manifest.json` | 擴充功能設定（MV3，僅在 kham.com.tw 生效） |
| `content.js` | 主邏輯：等開賣、選場次、票區搜尋、張數填寫、驗證碼輔助、狀態面板 |
| `inject.js` | 頁面主環境（`world: MAIN`）唯讀讀取網站的 XHR 回應與 `alert1` 提示 |
| `popup.html` / `popup.js` | 設定介面 |
| `background.js` | 背景服務，負責桌面通知 |

## 使用範圍與限制

- 只代替使用者在自己的瀏覽器裡填寫欄位、按網站原有的按鈕，所有請求都由網站原有程式碼發出
- 不辨識驗證碼、不繞過任何驗證機制、不代填帳號密碼、不代選座位
- **不要用無痕模式、不要開多視窗**：官方明講會導致驗證失敗
- 開賣時請保持分頁在**前景**：瀏覽器會把背景分頁的計時器節流到約每秒一次
- 倒數以本機時鐘為準，請先確認系統時間為自動同步
- 僅供個人自用，請遵守該網站的服務條款與購票規範；送出前自行確認場次、票種、張數與金額
- 網站改版時可能要調整 `content.js` 的定位條件（`#salesTable`、`input[KEY=…]`、`#ATYPE`、`#CHK`、`#GO_BUY2`）
